Search tools perform simple literal text searches against captured HTTP data.

Use short search terms that are likely to appear exactly in the HTTP data.

Available searchable fields:

* request_method
* request_url
* request_params
* request_headers
* request_cookies
* request_mime_type
* request_body
* response_status
* response_result
* response_headers
* response_cookies
* response_mime_type
* response_body
* browser_error

Select the most relevant field when the location of the information is known. Search across all fields when the location is uncertain.

Useful field selection:

* URLs, endpoints and paths -> request_url
* URL and query parameters -> request_params
* Request headers and authorization headers -> request_headers
* Request cookies -> request_cookies
* Request content such as POST data, JSON and form data -> request_body
* Response status codes -> response_status
* Response headers -> response_headers
* Response cookies -> response_cookies
* Returned HTML, JSON, JavaScript and other content -> response_body
* Browser and network failures -> browser_error

## find

`find` starts a literal text search across the HTTP records.

Use `find` to discover HTTP records containing evidence relevant to the current investigation objective.

Choose literal search terms based on the investigation objective and information discovered during previous searches.

When a concept may appear using several different terms, perform separate searches using individual literal terms.

Review the returned snippets and record IDs to determine the next useful investigation step.

## find_with_record_id

`find_with_record_id` starts a literal text search within one specific HTTP record.

Use it when an interesting record has been identified and searching within that request or response can provide additional relevant evidence.

Pass the `id` returned by a previous search result using the parameter named:

`record_id`

Choose additional literal search terms based on the information already discovered about that record.

## next

`next` returns the next page of results from the current `find` or `find_with_record_id` search.

Use it when additional matches from the current search are likely to provide useful evidence.

## Search strategy

1. Identify what evidence would help answer the current investigation question.
2. Choose a short literal search term likely to locate that evidence.
3. Select the most relevant searchable field when known.
4. Use `find` to discover matching HTTP records.
5. Review the returned snippets and record IDs.
6. Use `next` when additional matches from the current search are useful.
7. Use `find_with_record_id` when an interesting record requires closer investigation.
8. Choose further literal search terms from the evidence discovered.
9. Continue following useful evidence relevant to the current investigation objective.

Use the searchable field names exactly as listed above when specifying a field.
